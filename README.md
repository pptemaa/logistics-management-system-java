# Logistics Management System

Разрабатываемая на Java система управления логистикой с микросервисной архитектурой. Проект охватывает работу с пользователями, заказами на перевозку, водителями и складом. Цель системы — объединить основные логистические операции в едином API: от создания заказа и проверки доступности товара до назначения водителя и отслеживания доставки.

## Ключевые возможности

### Архитектура и инфраструктура

- Разделение бизнес-логики на пять компонентов: сервис авторизации, сервис заказов, сервис водителей, сервис склада и API Gateway.
- REST API для клиентских запросов и gRPC для взаимодействия между сервисами.
- Контейнеризация сервисов и зависимостей с помощью Docker Compose.

### Аутентификация и безопасность

- Регистрация и авторизация пользователей.
- Защита закрытых API-методов с помощью JWT.

### Данные и бизнес-процессы

- Хранение данных в PostgreSQL и кэширование часто запрашиваемых данных в Redis.
- Управление заказом на всех этапах: создание, назначение водителя, выполнение доставки и изменение статуса.
- Учёт водителей и их доступности.
- Учёт товаров и складских остатков.
- Передача событий между сервисами через Kafka там, где требуется асинхронное взаимодействие.

### Наблюдаемость

- Проверка состояния приложения через HTTP.
- Структурированное логирование для диагностики работы сервисов.

## Состояние проекта

Проект разрабатывается поэтапно. Созданы пять отдельных сервисов. В сервисе авторизации уже доступна регистрация пользователя с проверкой входных данных и хешированием пароля. Остальные перечисленные возможности описывают целевую систему.

## Запуск текущей версии

Нужны JDK 21 и Maven 3.9 или новее. Из корня репозитория соберите все сервисы:

```bash
mvn package
```

Для запуска отдельного сервиса используйте `mvn -pl <модуль> spring-boot:run`, например:

```bash
mvn -pl api-gateway spring-boot:run
```

| Модуль | Порт | Проверка состояния |
| --- | --- | --- |
| API Gateway | 8080 | `http://localhost:8080/actuator/health` |
| Auth Service | 8081 | `http://localhost:8081/actuator/health` |
| Order Service | 8082 | `http://localhost:8082/actuator/health` |
| Driver Service | 8083 | `http://localhost:8083/actuator/health` |
| Warehouse Service | 8084 | `http://localhost:8084/actuator/health` |

Ожидаемый ответ каждого эндпоинта: `{"status":"UP"}`.

### Регистрация пользователя

Запустите Auth Service и отправьте запрос на `http://localhost:8081/api/auth/register`:

```bash
curl -X POST http://localhost:8081/api/auth/register -H "Content-Type: application/json" -d '{"firstName":"Artem","lastName":"Portnov","email":"artem@example.com","password":"secure-pass-123"}'
```

Сервис возвращает `201 Created` с идентификатором и данными пользователя без пароля. Повторная регистрация с тем же адресом возвращает `409 Conflict`. Пока пользователи хранятся в памяти и исчезают после перезапуска сервиса; постоянное хранение будет добавлено следующим этапом.
