# Logistics Management System

Разрабатываемая на Java система управления логистикой с микросервисной архитектурой. Проект охватывает работу с пользователями, заказами на перевозку, водителями и складом. Цель системы — объединить основные логистические операции в едином API: от создания заказа и проверки доступности товара до назначения водителя и отслеживания доставки.

## Ключевые возможности

### Архитектура и инфраструктура

- Разделение бизнес-логики на пять компонентов: сервис авторизации, сервис заказов, сервис водителей, сервис склада и API Gateway.
- REST API для клиентских запросов и gRPC для взаимодействия между сервисами.
- Контейнеризация сервисов и зависимостей с помощью Docker Compose.

### Аутентификация и безопасность

- Регистрация и авторизация пользователей.
- Защита закрытых API-методов с помощью JWT.

### Данные и бизнес-процессы

- Хранение данных в PostgreSQL и кэширование часто запрашиваемых данных в Redis.
- Управление заказом на всех этапах: создание, назначение водителя, выполнение доставки и изменение статуса.
- Учёт водителей и их доступности.
- Учёт товаров и складских остатков.
- Передача событий между сервисами через Kafka там, где требуется асинхронное взаимодействие.

### Наблюдаемость

- Проверка состояния приложения через HTTP.
- Структурированное логирование для диагностики работы сервисов.

## Состояние проекта

Проект разрабатывается поэтапно. Созданы пять отдельных сервисов. В сервисе авторизации доступны регистрация и вход с выдачей JWT. Сервис водителей позволяет добавлять водителей, менять их статус и находить доступных водителей. Сервис склада ведёт каталог товаров, пополняет и резервирует остатки. Данные сохраняются в PostgreSQL, схемы баз создаются миграциями Flyway. Остальные перечисленные возможности описывают целевую систему.

## Запуск текущей версии

Нужны JDK 21 и Maven 3.9 или новее. Из корня репозитория соберите все сервисы:

```bash
mvn package
```

Для запуска отдельного сервиса используйте `mvn -pl <модуль> spring-boot:run`, например:

```bash
mvn -pl api-gateway spring-boot:run
```

| Модуль | Порт | Проверка состояния |
| --- | --- | --- |
| API Gateway | 8080 | `http://localhost:8080/actuator/health` |
| Auth Service | 8081 | `http://localhost:8081/actuator/health` |
| Order Service | 8082 | `http://localhost:8082/actuator/health` |
| Driver Service | 8083 | `http://localhost:8083/actuator/health` |
| Warehouse Service | 8084 | `http://localhost:8084/actuator/health` |

Ожидаемый ответ каждого эндпоинта: `{"status":"UP"}`.

### Регистрация пользователя

Для Auth Service сначала запустите PostgreSQL и задайте секрет подписи JWT длиной не менее 32 байт. Например, в PowerShell:

```powershell
docker compose -f compose.auth.yaml up -d
$env:JWT_SECRET = "<ваш-секрет-не-короче-32-байт>"
mvn -pl auth-service spring-boot:run
```

Затем отправьте запрос на `http://localhost:8081/api/auth/register`:

```bash
curl -X POST http://localhost:8081/api/auth/register -H "Content-Type: application/json" -d '{"firstName":"Artem","lastName":"Portnov","email":"artem@example.com","password":"secure-pass-123"}'
```

Сервис возвращает `201 Created` с идентификатором и данными пользователя без пароля. Повторная регистрация с тем же адресом возвращает `409 Conflict`. Для другого подключения к PostgreSQL задайте переменные `DB_URL`, `DB_USER` и `DB_PASSWORD`.

Для входа отправьте `POST http://localhost:8081/api/auth/login` с JSON `{"email":"artem@example.com","password":"secure-pass-123"}`. Ответ содержит `accessToken`, тип `Bearer` и время истечения токена. Неверные учётные данные возвращают `401 Unauthorized`. Защита методов других сервисов будет добавлена на одном из следующих этапов.

### Водители

Запустите базу данных и Driver Service в отдельных терминалах:

```bash
docker compose -f compose.driver.yaml up -d
mvn -pl driver-service spring-boot:run
```

`POST http://localhost:8083/api/drivers` создаёт водителя по JSON с полями `name`, `phone`, `licenseNumber` и `car`. Новый водитель получает статус `offline`. Список доступен по `GET /api/drivers`, отдельная запись — по `GET /api/drivers/{id}`. Повторный номер удостоверения возвращает `409 Conflict`.

`PATCH /api/drivers/{id}/status` с JSON `{"status":"available"}` меняет статус. Допустимые значения: `offline`, `available`, `busy`, `break`, `unavailable`. Запрос `GET /api/drivers?status=available` возвращает доступных водителей. Для другого подключения к базе задайте `DRIVER_DB_URL`, `DRIVER_DB_USER` и `DRIVER_DB_PASSWORD`.

### Склад

Запустите базу данных и Warehouse Service в отдельных терминалах:

```bash
docker compose -f compose.warehouse.yaml up -d
mvn -pl warehouse-service spring-boot:run
```

`POST http://localhost:8084/api/stock` создаёт товар по JSON `{"productName":"Ноутбук","quantity":5,"price":899.99}`. Каталог доступен по `GET /api/stock`, отдельная позиция — по `GET /api/stock/{id}`. Название товара должно быть уникальным; количество и цена не могут быть отрицательными.

`POST /api/stock/{id}/reserve` с JSON `{"quantity":2}` резервирует товар, уменьшая доступный остаток. Если товара недостаточно, сервис возвращает `409 Conflict` и не меняет остаток. `POST /api/stock/{id}/replenish` с тем же форматом увеличивает остаток. Для другого подключения к базе задайте `WAREHOUSE_DB_URL`, `WAREHOUSE_DB_USER` и `WAREHOUSE_DB_PASSWORD`.
